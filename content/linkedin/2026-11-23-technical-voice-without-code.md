You do not need to write code to be the technical voice.

Women who move from development into management sometimes hear the same thing: "You are not technical anymore."

I was a senior .NET and SharePoint developer for years. Today I am a project manager. I do not review code at work. But I still discuss architecture with tech leads as a peer.

Technical credibility is not about typing code. It is about the questions you ask:

→ "What happens when this service is down?"
→ "Which part of this estimate are we least sure about?"
→ "What would we have to undo if we change this later?"

And about how you use them: challenge the estimate in the planning meeting, then back your tech lead in front of the client.

If you left development, you did not leave the knowledge behind. Keep asking the questions that only someone who has built things would ask.

What question makes you sound most technical in a meeting?
