The legacy code nobody understands is your best AI use case.

Every team has one: the old system everyone is afraid to touch. The person who wrote it left. The documentation is a wiki page from years ago.

Most teams try AI first on new code. But new code is where people already know what they want. Old code is where nobody does.

With my teams, we used AI to document more than five existing codebases, in different technologies. What worked was a simple loop:

→ Give AI one module at a time, not the whole system
→ Ask for what it does, its inputs and outputs, and what looks risky
→ Ask the person who knows the code best to review the result
→ Save the reviewed version next to the code

The review step is not optional. AI explains code with confidence, including the parts it gets wrong.

Start with the module that causes the most questions in your team. One reviewed page is already more than you have today.

Which part of your system would you document first?
